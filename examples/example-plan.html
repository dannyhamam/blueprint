    Add rate limiting to the public API

    Stop a single API key from starving everyone else, without adding infrastructure or breaking well-behaved clients.

    Blueprint Sep 24, 2026 22:58 uppi-order-portal

    01Overview

    One partner’s retry loop has slowed the API for every tenant three times this month. Add a per-key request budget in the existing app, observe real traffic for 48 hours, then enforce with 429 and Retry-After. No new infrastructure.

    02Solution

    Add an in-memory request budget per API key, after authentication and before route handlers. Reuse the existing tenant settings and request logs. Each replica tracks its own budget, so three replicas can allow up to 3× the configured limit; exact global limits would require shared storage.

    3. Check the key’s request budget

      src/api/middleware/rateLimit.tsNew

      Keep an in-memory token bucket per key, using its tenant override or the proposed 60/min default. Requests within budget continue to the existing route handlers. Over-budget requests return 429 with Retry-After; in log-only mode they are recorded and allowed through. Prune idle buckets every five minutes.

      VerifyTest refill, cleanup, overrides, and off/log/enforce behavior.
