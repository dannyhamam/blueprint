# Design exploration prompt

Paste this into Claude Design (or any design tool) to explore alternative looks for the Blueprint page. It fixes the content and structure so the tool redesigns the *page*, not the product. Attach `examples/example-plan.html` as the current baseline if the tool accepts files.

---

Design a single-page HTML document that displays a software implementation plan. The reader is a developer who works in a terminal all day and opens this page in a browser to read a plan an AI agent just wrote, so they can approve, question, or redirect it. They read it once, decide, and close it. Reading speed and orientation matter more than delight.

**Default structure.** Two sections: Overview (a simple visual of the change and a short explanation of what changes and why) and Solution (how it works, connected file nodes in request execution order, each showing the change and verification; supporting tests, config, and docs expand beside the relevant node, and only the supporting detail that matters). Context, alternatives, risks, and checks are optional subsections, not mandatory navigation entries. Add a top-level section only when a topic needs independent review. Navigation builds from the sections present. Above them, a header with a title, one-sentence subtitle, a metadata line with Blueprint, date/time, and repository name. No footer.

**Constraints.** Single HTML file, CSS inline, no web fonts (system serif and sans stacks only), no images, no stock icons, no emoji, no gradients; a small CSS brand mark. Diagrams are Mermaid rendered client-side or inline SVG, so design a "figure" container that flatters an SVG on a white or near-white ground. One accent color connects the brand, proposed change, chosen option, current phase, active TOC entry, decision callouts, and links. Green/amber/red communicate status or severity; green may also mark verification labels. Must read well at 1280px wide and reflow at 800px. Print stylesheet optional.

**Current direction (to depart from or refine).** Warm gray canvas, white diagram and step cards, bold system-sans headline, 15px body, small mono section numbers, 248px fixed sidebar and a 900px content area. A before/after map leads the overview, followed by a short explanation. Avoid approval prompts and scope panels; weave essential constraints into the solution. The navigation becomes a horizontal strip on mobile. Tables scroll within their own region. Include keyboard focus, reduced motion, and print styles.

**Deliver** the full HTML with the CSS in a single `<style>` block using CSS custom properties for every color and font so the tokens can be lifted into the existing template. Use realistic placeholder content for a plan titled "Add rate limiting to the public API" with Overview and Solution, a before/after map, a request flow from SDK to API entry point to limiter and back to the SDK on a 429, essential tradeoffs explained inline, and verification statements beside the relevant files. Do not add a completion checklist. Avoid filler sections.
